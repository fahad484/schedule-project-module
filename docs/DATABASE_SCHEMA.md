This document provides a comprehensive reference for the PostgreSQL database schema utilized by the Appointment Booking System, defined and managed via [Drizzle ORM](file:///c:/Users/Hp/OneDrive/Apps/appointment-booking/src/db/schema/index.ts) on [Neon Serverless PostgreSQL](file:///c:/Users/Hp/OneDrive/Apps/appointment-booking/src/lib/db.ts).

## 1. Schema Overview & Architecture

The database architecture is designed with strict relational constraints, strong typing via PostgreSQL Enums, atomic cascading operations, and dedicated composite unique indexes to prevent concurrency anomalies such as double-booking.

## 2. PostgreSQL Enumerated Types (Enums)

The system defines four native PostgreSQL enums to restrict column values at the storage engine level, preventing illegal state transitions.

### 2.1. `user_role`
Defines authorization privileges across the platform.

```sql
CREATE TYPE "user_role" AS ENUM ('patient', 'doctor', 'admin');
```

| Value | Description |
| :--- | :--- |
| `patient` | Standard consumer capable of searching doctors, booking slots, and submitting reviews. |
| `doctor` | Healthcare practitioner managing weekly schedules, leaves, and patient consultations. |
| `admin` | System administrator with full oversight, user management, and platform analytics. |

### 2.2. `appointment_status`
Tracks the chronological state lifecycle of clinical consultations.

```sql
CREATE TYPE "appointment_status" AS ENUM (
  'scheduled',
  'confirmed',
  'completed',
  'cancelled',
  'no_show'
);
```

| Value | Description |
| :--- | :--- |
| `scheduled` | Initial state upon booking creation by patient. |
| `confirmed` | Explicitly acknowledged and accepted by the doctor. |
| `completed` | Consultation concluded; notes recorded; enables patient review submission. |
| `cancelled` | Voided either by patient, doctor, or administrator. |
| `no_show` | Patient failed to attend without prior cancellation. |

### 2.3. `notification_type`
Categorizes transactional and operational alerts sent to users.

```sql
CREATE TYPE "notification_type" AS ENUM (
  'appointment_booked',
  'appointment_confirmed',
  'appointment_cancelled',
  'appointment_rescheduled',
  'appointment_reminder',
  'review_received',
  'general'
);
```

### 2.4. `day_of_week`
Enforces standard calendar weekdays for recurring doctor availability templates.

```sql
CREATE TYPE "day_of_week" AS ENUM (
  'monday',
  'tuesday',
  'wednesday',
  'thursday',
  'friday',
  'saturday',
  'sunday'
);
```

## 3. Database Table Definitions

### 3.1. `user` Table
Stores base profile and authentication identities for all platform actors. Compatible with Better Auth user specifications while extending custom medical attributes.

| Column | PostgreSQL Type | Nullable | Default | Constraints / References | Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `id` | `TEXT` | No | None | `PRIMARY KEY` | Unique string identifier generated by Better Auth. |
| `name` | `TEXT` | No | None | | User full legal name. |
| `email` | `TEXT` | No | None | `UNIQUE` | User email address used for login and notifications. |
| `email_verified` | `BOOLEAN` | No | `false` | | Email verification status flag. |
| `image` | `TEXT` | Yes | `NULL` | | Avatar or profile photo URL. |
| `created_at` | `TIMESTAMP` | No | `NOW()` | | Record creation timestamp. |
| `updated_at` | `TIMESTAMP` | No | `NOW()` | | Record last modified timestamp. |
| `role` | `user_role` | No | `'patient'` | Enum validation | Access tier: `patient`, `doctor`, or `admin`. |
| `phone` | `VARCHAR(20)`| Yes | `NULL` | | Contact telephone or mobile number. |
| `date_of_birth` | `DATE` | Yes | `NULL` | | Patient/Doctor date of birth for records. |
| `address` | `TEXT` | Yes | `NULL` | | Residential or postal address. |

**Indexes & Constraints:**
- `user_email_unique`: Unique constraint on `email`.

### 3.7. `doctor_availability` Table
Stores recurring weekly working schedules, operational shifts, and default slot lengths.

| Column | PostgreSQL Type | Nullable | Default | Constraints / References | Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `id` | `UUID` | No | `gen_random_uuid()` | `PRIMARY KEY` | Availability window identifier. |
| `doctor_id` | `UUID` | No | None | `REFERENCES doctor_profile(id) ON DELETE CASCADE` | Doctor owning this availability block. |
| `day_of_week` | `day_of_week`| No | None | Enum check | Day of week (`monday` through `sunday`). |
| `start_time` | `TIME` | No | None | | Shift starting time (e.g., `09:00:00`). |
| `end_time` | `TIME` | No | None | | Shift ending time (e.g., `17:00:00`). |
| `slot_duration_minutes`| `INTEGER` | No | `30` | | Duration per consultation slot (10 - 120 mins). |
| `is_active` | `BOOLEAN` | No | `true` | | Toggle to activate/deactivate specific shift without deleting. |
| `created_at` | `TIMESTAMP` | No | `NOW()` | | Timestamp created. |

**Indexes & Constraints:**
- `idx_doctor_day_time`: `UNIQUE (doctor_id, day_of_week, start_time)` — Guarantees a doctor cannot configure duplicate overlapping shifts on the same day at the same starting time.
- `idx_availability_doctor`: Index on `doctor_id`.

### 3.9. `appointment` Table
The central transactional record documenting patient bookings, scheduled times, clinical status, and cancellation audits.

| Column | PostgreSQL Type | Nullable | Default | Constraints / References | Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `id` | `UUID` | No | `gen_random_uuid()` | `PRIMARY KEY` | Unique appointment identifier. |
| `patient_id` | `TEXT` | No | None | `REFERENCES user(id) ON DELETE CASCADE` | Patient booking the consultation. |
| `doctor_id` | `UUID` | No | None | `REFERENCES doctor_profile(id) ON DELETE CASCADE` | Doctor fulfilling the consultation. |
| `appointment_date`| `DATE` | No | None | | Consultation calendar date (`YYYY-MM-DD`). |
| `start_time` | `TIME` | No | None | | Slot start time (`HH:MM:SS`). |
| `end_time` | `TIME` | No | None | | Slot end time (`HH:MM:SS`). |
| `status` | `appointment_status`| No | `'scheduled'`| Enum check | Current workflow state. |
| `reason` | `TEXT` | Yes | `NULL` | | Patient-provided symptoms or reason for visit. |
| `notes` | `TEXT` | Yes | `NULL` | | Doctor clinical consultation notes. |
| `cancelled_at` | `TIMESTAMP` | Yes | `NULL` | | Timestamp when cancellation was executed. |
| `cancelled_by` | `TEXT` | Yes | `NULL` | | User ID of party initiating cancellation. |
| `cancellation_reason`| `TEXT` | Yes | `NULL` | | Explanation provided for cancellation. |
| `created_at` | `TIMESTAMP` | No | `NOW()` | | Timestamp booking was submitted. |
| `updated_at` | `TIMESTAMP` | No | `NOW()` | | Timestamp appointment was last updated. |

**Indexes & Concurrency Protection:**
- `idx_unique_doctor_slot`: **`UNIQUE (doctor_id, appointment_date, start_time)`** — **Critical concurrency defense**. Guaranteed by PostgreSQL storage engine to reject race conditions where two concurrent requests attempt to reserve the same doctor at the exact same date and start time.
- `idx_appointment_patient` on `patient_id` (accelerates patient dashboard queries).
- `idx_appointment_doctor` on `doctor_id` (accelerates doctor agenda queries).
- `idx_appointment_date` on `appointment_date` (accelerates day-level schedule searches).
- `idx_appointment_status` on `status` (optimizes status filtering).

## 4. Complete Foreign Key Relationships & Cascade Matrix

The following matrix documents all referential integrity rules and delete behaviors across the schema:

| Child Table | Foreign Key Column | Parent Table | Parent Key | On Delete Rule | Business Logic Rationale |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `session` | `user_id` | `user` | `id` | `CASCADE` | When a user is purged, all active web sessions are destroyed immediately. |
| `account` | `user_id` | `user` | `id` | `CASCADE` | Purging user removes OAuth tokens and credentials. |
| `doctor_profile` | `user_id` | `user` | `id` | `CASCADE` | Deleting a doctor user deletes their public profile. |
| `doctor_profile` | `specialty_id` | `specialty` | `id` | `RESTRICT` (Default) | Cannot delete a medical specialty while doctor profiles are actively assigned to it. |
| `doctor_availability`| `doctor_id` | `doctor_profile` | `id` | `CASCADE` | Deleting a doctor profile purges recurring shift schedules. |
| `doctor_time_off` | `doctor_id` | `doctor_profile` | `id` | `CASCADE` | Purging doctor clears associated leaves. |
| `appointment` | `patient_id` | `user` | `id` | `CASCADE` | Removes appointments when patient account is wiped. |
| `appointment` | `doctor_id` | `doctor_profile` | `id` | `CASCADE` | Removes appointments when doctor profile is wiped. |
| `review` | `appointment_id` | `appointment` | `id` | `CASCADE` | Review belongs strictly to one appointment. |
| `review` | `patient_id` | `user` | `id` | `CASCADE` | Cleans reviews if patient profile is purged. |
| `review` | `doctor_id` | `doctor_profile` | `id` | `CASCADE` | Cleans reviews if doctor profile is purged. |
| `notification` | `user_id` | `user` | `id` | `CASCADE` | Notification records belong solely to their owner. |

## 5. Drizzle ORM Schema Implementation Reference

In the source tree, all schemas and relations are exported from [`src/db/schema/index.ts`](file:///c:/Users/Hp/OneDrive/Apps/appointment-booking/src/db/schema/index.ts).

### Example Table Export Snippet:
```typescript
export const appointment = pgTable(
  "appointment",
  {
    id: uuid("id").defaultRandom().primaryKey(),
    patientId: text("patient_id")
      .notNull()
      .references(() => user.id, { onDelete: "cascade" }),
    doctorId: uuid("doctor_id")
      .notNull()
      .references(() => doctorProfile.id, { onDelete: "cascade" }),
    appointmentDate: date("appointment_date").notNull(),
    startTime: time("start_time").notNull(),
    endTime: time("end_time").notNull(),
    status: appointmentStatusEnum("status").notNull().default("scheduled"),
    reason: text("reason"),
    notes: text("notes"),
    cancelledAt: timestamp("cancelled_at"),
    cancelledBy: text("cancelled_by"),
    cancellationReason: text("cancellation_reason"),
    createdAt: timestamp("created_at").notNull().defaultNow(),
    updatedAt: timestamp("updated_at").notNull().defaultNow(),
  },
  (table) => [
    uniqueIndex("idx_unique_doctor_slot").on(
      table.doctorId,
      table.appointmentDate,
      table.startTime
    ),
    index("idx_appointment_patient").on(table.patientId),
    index("idx_appointment_doctor").on(table.doctorId),
    index("idx_appointment_date").on(table.appointmentDate),
    index("idx_appointment_status").on(table.status),
  ]
);
```
